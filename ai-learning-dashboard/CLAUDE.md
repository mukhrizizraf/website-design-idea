## Architecture

- **Data:** `public/skills.js` sets `window.SKILL_DATA` (categories, levels, sources, featured, collections, skills). Both pages render from it, and `tests/skills.test.mjs` validates it, so a typo fails the tests rather than the live page.
- **Install steps are generated, not stored:** `install()` in `public/shelf.js` builds the Claude Code sentence, PowerShell and Terminal commands and the ZIP link from `sources[src].repo/branch/dir` (`root: true` means the whole repo is one skill; `plugin: [...]` means Claude Code `/plugin` commands). A skill whose source has no `repo` shows "no public download link".
- **Homepage** `public/index.html` (`<html data-wall="manual">`, `<body data-page="home">`): one screen, no page scroll, app style with minimal text. The inline Three.js module shows 9 cartoon book covers. On load they fall to random spots and crawl into a fan (`scatter`, `introOn`); then the fan is an endless loop turned by wheel, trackpad, swipe, drag or arrow keys (`loopPos`/`loopTarget`, `loopPose()`), and it advances by itself after 4 s idle. Tap a side book to bring it to the front; tap the front book to open the pop-up dialog. Book colours come from `CARTOON`/`RAINBOW` (same 10-colour order as the library). Glossy candy shapes from `wallpaper.js` `createField()` float behind the books on laptops (none on phones). On top: the logo bar, one `Browse skills` button and the category dock (`toys.js`). The old scroll poses (`poses`, `?pose=0..3`) and supernova code are still in the file but only used with `?pose`.
- **Library** `public/shelf.html` + `shelf.js` + `shelf.css` (rewritten clean on 12 Nov 2026): laptop = shelf rail (`.rail`: Home, shelf tabs `#tabs`, Guide) + one sticky title bar (`.bar`: title `#library-title`, count `#result`, search `#q`, Easy `#easy`, dice `#surprise`) + cover grid; phone = top bar, sticky shelf strip, 2-column grid, tab bar (Home, Library, Guide). Detail sheets (`#detail`) slide up on phones; `#skill=<id>` deep links; `?cat=<id>`; `#saved` and `#guide` hashes. Hidden compatibility elements (`#library-description`, `#library-count`, `#location-label`, `#storage-note`, `#share-page`) stay because `shelf.js` still writes to them. Saving is hidden in the UI.
- **Book covers** (`.book` in `shelf.css`, `row()` in `shelf.js`): cover colour, thick ink outline, ink drop shadow, white badge with the skill symbol, white label with name and level. `COVERS` (10 colours) is assigned in grid order (`coverN`), so neighbours never match but a skill's colour can differ from the homepage (a jury finding, see below). Symbols: `ShelfToys.G` / `SKILL_GLYPH` in `toys.js`.
- **Motion** `public/motion.js` (both pages): library cards rise in (`.fx-in`, `.fx-wait` until scrolled into view, via a MutationObserver on `#groups`), 3D tilt with sheen under the mouse (`.lean`). Nothing in the library moves by itself (owner request). Does nothing with reduced motion.
- **`public/wallpaper.js`** (ES module): exports `createField()` for the homepage shapes; when a page has no `data-wall="manual"` it would start its own renderer, but no page loads it that way any more. The library no longer loads `wallpaper.js` or `vibe.js` (owner: no moving background on the skills page).
- **`public/app.js`** (library): install prompt, service worker. Its sticker code only runs if a `#floaters` element exists (it no longer does).
- **Shared** `public/pop.css`: category colours (`[data-cat]`), the category toys' CSS, the old dock (`.category-dock`, also styles `.tabbar`) and dialog pop animation. Both pages load it, so `shelf.css` overrides its `.tabbar` and `dialog.pop` rules explicitly.
- **Unused drafts:** `particles.js` (particle book → cube → shelf story), `skillcube.js` (block-cube hero), `vibe.js`. `showcase.*`, `room.jpg` and `skill-shelf-icons.png` are leftovers from an earlier design (`tests/showcase.test.mjs` still checks `showcase.js`).
- `server.mjs` serves only an explicit allowlist of files (`const files={...}`): add any new public file there or `npm start` returns 404 for it. Its CSP hashes inline scripts in every `.html`. It also hosts a token-protected lesson API; `bridge.mjs` is a stdio MCP server (`save_lesson`); `public/model.js` remains for them and the tests.

## Things that are easy to get wrong

- The `/jury` tool's `--nav` step on the homepage sometimes reports "no link could be clicked" and lists `#front-link` as covered. `#front-link` is hidden until Tab on purpose, and a real click on `Browse skills` works (checked with Playwright on the live site, also after wheeling the fan). Treat that note as a tool artifact. `--crawl` also never reaches a skill sheet: shoot `shelf.html#skill=<id>` separately. Its phone scroll frames move the window with `scrollTo`, so an open sheet looks frozen while the page moves behind it; a real wheel or swipe scrolls the sheet (checked).

- Prompt Motion clips play from `media.prompt-motion.com` (credited, never copied). Avast on this PC blocks that host (curl gets a reset), so clips can't be checked from here; the sheet shows a "blocked" note when the poster fails. Links to prompt-motion.com pages stay off after an antivirus warning.
- Headless Edge with `--use-angle=swiftshader --enable-unsafe-swiftshader` renders the WebGL homepage for screenshots; its frame rate is not representative (use it only for before/after ratios). Screenshots need a fresh `--user-data-dir` per run; never kill all `msedge.exe` (it closes the owner's browser). Opened as `file://`, pages can't read images into WebGL.
- Performance: no `backdrop-filter` over moving 3D (it is recomputed every frame), no physical/transmission glass on the home books, no constantly spinning CSS 3D on the library.

## Owner preferences (from past feedback)

- Plain, simple English in the UI, and as little text as possible: "the app is for skills, no need to explain". No headlines, paragraphs or footers on the homepage.
- It must feel like an app on phones **and** laptops (compact bars, icons, big touch targets), not a website.
- Bright and colourful; no mint/green accent, no brown theme, no dark theme, no sound. Book colours must be clearly different from their neighbours.
- No "just ask" / "Claude can do that" lettering or anything that suggests the site is sponsored by Claude.
- Loves the 3D book scenes (falling, crawling, fan loop); dislikes flat or "lava lamp" backgrounds and moving backgrounds on the skills page.
- Changes direction often in short messages. Agree a direction (a page with mockups) before building, then take feedback against it; publish so the owner can check on their phone. Symmetry matters: rows and columns must line up, and the layout must not squash on short laptop screens.
